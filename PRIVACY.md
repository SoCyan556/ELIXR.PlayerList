# Privacy design

The player list and desktop overlay group your account first, actual VRChat friends next, and other players last, alphabetically within each group. Friendship is read from the existing authenticated VRChat profile requests and cached in memory for the signed-in account; no extra friend-list download is required. It is not inferred from community labels and is not saved into recent-player history. Recent keeps encounter-time order.

The Search tab sends the display name you submit directly to VRChat using your existing native authenticated session. Checking a search result uses the same public tag catalogs, VRChat public-group lookup, and bounded image cache as the instance roster. Search text and results are held only in memory and cleared on leaving Search or signing out; no search history is saved or sent to ELIXR/GitHub. Only the selected result triggers group and portrait lookups. Search results never enter the instance or overlay roster. VRChat may retain its own request logs. Community feeds and private memberships may be incomplete; absence of a matching tag is not a safety guarantee.

The optional startup/manual update check contacts the public GitHub releases
API for SoCyan556/ELIXR.PlayerList. GitHub receives ordinary network metadata
(such as IP address), never VRChat credentials, account IDs or player lists.
Only clicking Update now downloads and launches an installer, after native
size/SHA-256 verification. Download files are held under LocalAppData/ELIXR/
PlayerList/Updates. Maybe later dismisses the prompt without installing.

The Vue frontend is bundled locally and hosted in WebView2, not loaded from an external website. The login form passes the submitted password or verification code once to the native service and clears the form value. Native session cookies are never sent back to JavaScript. WebView2 password autosave and general autofill are disabled.

The optional always-on-top desktop overlay displays the same local roster and settings in a second bundled WebView, using the existing browser environment. It does not start another log reader or issue additional backend requests. Its restricted bridge accepts readiness, close, header dragging, fixed compact/expanded sizing, tag-display filters, copying a validated user ID, and selecting a current roster player's profile in the main ELIXR window. It cannot submit login credentials or launch external URLs. Signing out or closing the main app closes the overlay; its visibility is not restored automatically on startup. The overlay is a visible desktop window: take care when sharing your screen.

Overlay width, height and desktop coordinates are saved locally in settings.json and are never transmitted. The resize editor is a temporary native dimming window: it does not capture, record, or send the contents of your desktop. Save commits the layout; Cancel/Escape restores its previous bounds. Ordinary moves and size changes are saved after a short debounce and when the overlay closes. Restored bounds are clamped to the currently available desktop if monitor geometry changes.

ELIXR Player List reads local VRChat client logs to determine the current instance roster. Recent Players stores up to 1,000 distinct encountered IDs, display names, encounter timestamps, and the last captured community-tag/local-portrait snapshot from the past 30 days. JSON history files stay under `%LOCALAPPDATA%/ELIXR/PlayerList/RecentPlayers`, partitioned by a hash of the signed-in account ID. History is not uploaded, is not encrypted, and is hidden on sign-out or account change. Incomplete IDs, your own account, and Search results are not recorded. Only the latest VRChat log observed while the tool runs is replayed; this is not a scan of all past sessions. With ELIXR closed, the history folder can be removed to discard saved records. The next running session can reconstruct encounters from the current log. Settings also remain local.

While signed in, the native image service requests public profile image fields for encountered player IDs from VRChat. It does not store the full user-profile response or send these IDs to ELIXR/GitHub. Only raster images are cached on disk (opaque hash filenames, bounded to 32 MiB); profile image selection is cached in memory. Images are served to both desktop windows through a local WebView2 virtual host. VRChat auth cookies are used only for the fixed VRChat API host, never forwarded to CDN hosts or JavaScript. Redirects, response sizes and raster signatures are checked; unavailable images fall back without blocking the roster. Cached portraits persist across app restarts; they may be removed by deleting the PlayerImages cache while ELIXR is closed.

The native tag service downloads the three public FewTags/ETags/etags-groups catalogs from raw.githubusercontent.com through a separate cookie-free HTTP client. GitHub never receives VRChat credentials, encountered player IDs, or per-player tag queries. Public feed copies are cached locally under `%LOCALAPPDATA%/ELIXR/PlayerList/TagFeeds`. While signed in, the service requests encountered players' public group memberships from VRChat's HTTPS API to match group IDs against the group catalog. Membership results are held in a bounded memory cache, not persisted, and are cleared on account change. Rate limits and network failures never prevent local roster display.

Starting with 0.1.2, after successful local VRChat authentication, the tool sends only your own VRChat user ID to `https://elixrvr.com/api/player-list/usage`. ELIXR privately stores that ID and its server-side first-recorded timestamp for a lifetime unique-user count and an admin-only adoption chart. Existing IDs are never overwritten or counted again, including across devices and reinstalls. This is client-reported usage, not independent proof of account ownership, and grants no access or permissions. Earlier versions did not register users, so historical usage cannot be recovered. Offline failures are non-blocking and retry on a later sign-in. A local opaque SHA-256 marker avoids repeat submissions after success. UI previews and smoke tests never register users.

Current authentication sends secrets only to VRChat's HTTPS API. Passwords, auth cookies, instances, encountered players, launch counts, hardware identifiers, fingerprints and activity history are never sent to ELIXR. Like other HTTPS requests, the registration request necessarily passes ordinary connection metadata to the website's hosting provider; the application registration record does not include IP addresses. Registration is independent of Remember me, which controls only local session storage.

Remember me stores only the auth/twoFactorAuth session cookies and their expiry in session.bin encrypted with Windows DPAPI CurrentUser. Passwords and verification codes are never written to storage or logs. Without Remember me, cookies live only in memory. Startup validates the saved session; rejected/expired sessions are removed, while a temporary network failure allows retry. Logout clears memory and the saved session and attempts server logout. Logging out does not remove a lifetime first-use record.
